# Stock Mine

本机优先的中国 A 股技术选股工作台。

## 买入预警收盘跟踪（2026-09-14）

工作台顶部新增“预警跟踪”，也可直接打开 `/?view=alert-monitor`。

- 从已保存的真实数据“买入预警”批次导入，不把观察机会、示例数据或历史回测信号混入。
  同股同日合并，保留首次批次和同日批次数；不同日期的入选分别记录。
- **基准是实际入选日的未复权收盘价**，不是筛选时默认使用的前一日信号 K 线价格。
  入选时间取批次完成并保存的时间；非交易日入选使用上一交易日收盘，并单独展示基准日期。
  当天尚未收盘或缺少有效收盘价时等待更新，不用盘中价、前复权缓存或零值填补。
- 涨跌幅 = `(最新完整交易日未复权收盘价 / 入选基准收盘价 - 1) × 100%`。
  这是价格变化，未计分红、除权影响、交易费用，不是总收益率或实际交易收益。
  基准价首次确认后冻结；每日快照落库，同日重复更新不会制造多条记录。
- “入选后交易日数”以交易日历计算，基准日为0，下一市场交易日为1，不把周末、节假日算进去。
  可按天数、涨跌幅、入选日期、股票/行业、行情状态筛选；上下限均包含，2至2只看第2个交易日。
  默认每股最新一条，也可查看全部入选记录、排序、翻页和每日跟踪记录。
- 服务器部署默认启用北京时间交易日16:00更新，每次仅2个取数线程；当日部分失败有限重试，
  每个交易日最多4次自动尝试。重启后补最近一次已到时但未完成的更新，不依赖浏览器或本机在线。
  手动“更新收盘价”可立即补数，使用最新已完成交易日，不在盘中伪造当日收盘。
- 旧行情与缺失数据明确显示“未更新”或“待收盘价”，不会冒充当天涨幅，也不会通过涨跌幅筛选。
  原筛选结果、观察池、策略参数和历史预警不被改写。上线前的日度快照不会被伪造。

定时开关为 `STOCK_MINE_MONITOR_SCHEDULE_ENABLED=1`，已加入服务器 Compose；
本机直接运行默认不启用定时，可通过环境变量开启。手动更新不受这个开关限制。
定时任务沿用单 API 进程约束，日历超出支持范围时停止计算，不猜测交易日。

## 两层精准点引擎（2026-09-10）

新筛选默认使用 `precision_engine=platform_events`，旧批次仍沿用原引擎，不覆盖已有预警和观测池。
工作台和详情均可选择 `legacy`（原版）、`pivot_fixed`（仅修最终容差）、`platform_events`（两层事件）。
这是规则实现的升级，**尚不等于已经证明能提高收益**。

- 大级别 ZigZag 保留为趋势参照；精准点另由局部转折、阻力验证、支撑验证产生。
- 阻力取最高价、支撑取最低价，反应由后续收盘确认。阈值为极值日 ATR20 的1倍与价格1%中较大值，
  不是固定间隔N根。已确认事件不会被未来更大的峰谷删除。
- 同一价位带内反复摩擦不累加：必须先离开价位带达到反应幅度，再次回来才算独立试探。
  同次转折的多个识别来源合并；保存整段最高/最低价，不挑最贴线K线凑点。
- 所有贡献点都在最终代表线的±2%价位带内，支撑和阻力分别计数、共同构线。
- 两个独立事件形成候选，三个形成已验证平台。收盘上穿代表线进入观察；
  达到0.6%缓冲后确认突破；突破后1至10日（可设1至60日）符合缩量回踩、守线、距离和MA趋势才发买入预警。
  突破前尚未验证的平台不会因本次回踩补点而升级本次买入预警。
- 事件版的观察不会被“尚未回踩”过滤。`require_pullback` 开关仅保留给旧峰谷模式；
  事件版买入预警始终要求回踩，观察和预警分开显示。
- 突破冻结当时线版本和构线证据；失效不擦除历史事件，但再次尝试要重新离带并通过路径过滤。
  股价1.50倍、连续30日有效收线上、关闭突破量比这三项既定参数保持不变。
- 点标记画在发生日，悬停显示确认日、来源、整段极值；策略仅在确认后使用。
  详情的分析日期可回到历史日，历史预警可恢复冻结线；不把今天的行业、股东或新闻回填历史。
- 股东比例缺失不能当零，旧缓存不能伪造集中度变化；行业归属冲突、未核验或过期时不加减行业分；
  行情更新失败停止当前交易预警，零成交量日不确认事件。

## 功能

- 手动触发 A 股技术筛选，**默认扫描全部股票**（约 5000 只，4 线程并发；耗时取决于数据源限流）
- **实时进度**：进度条 + 「已处理 / 命中 / 失败 / 当前股票」，命中的股票边扫边出现在列表里
- **扫描在服务端后台运行**：中途可以切走或刷新页面，回来会自动接续显示进度
- **单股分析**：输入 6 位代码即可单独分析；未入选时给出卡在哪一步的诊断（数据不足 / 未找到精准线 / 有精准线但不满足条件 / 取数失败），而不是一句「无信号」
- 两层信号：`买入预警` 与 `观察机会`
- 精准线只使用突破前已经确认的构线证据，历史预警保存当时的线版本
- 默认使用前一交易日完整 K 线，减少盘中信号漂移
- 扫描数量设为 `0` 时扫描全部股票；限量扫描会均匀覆盖整个股票池，进度分母是本次实际扫描的数量
- 数据源失败自动重试 3 次；`auto` 模式会在单次请求失败或返回空数据时从 AData 回退到 AKShare
- SQLite 保存筛选批次和观测池；观测池固定记录加入价，并展示最新价、涨跌额和累计涨跌幅
- 刷新页面始终恢复最近一次成功完成的筛选；失败或中断任务不会覆盖已有预警
- 点击股票打开独立详情页，查看完整个股 K 线、MA5/10/20/60、成交量、MACD、精准线与历史预警点
- 详情页展示公司资料、最新股东户数、前十大股东、筹码利好/利空标记和个股新闻
- 展示所属行业风险、行业指数完整 K 线，并将有限幅度的行业修正计入综合分
- 单股历史时点化复盘，以及对本次全部入选股票执行后台批次复盘和成功率汇总
- 数据源优先尝试 `adata`，当前依赖清单默认安装 `akshare`；页面也提供 `sample` 示例数据

所有提示都是技术分析预警，不构成投资建议。

## 旧峰谷引擎的突破后回调筛选

本节的硬过滤及最近突破搜索描述适用于 `legacy` / `pivot_fixed`；
事件版的候选、观察、预警和冻结突破行为见上面的两层引擎说明。

新筛选默认开启 `require_pullback=true`，精准线分支必须在信号日完成突破后的缩量回踩，
未突破、突破当天、未回踩、回踩失败或已离开回踩位置的股票不再混入该分支。
精准线分支默认关闭突破量比过滤（`require_breakout_volume=false`），按收盘价上穿精准线确认突破，
仍保留原有0.6%的突破缓冲：前收盘不高于线价1.006倍、本日收盘达到或超过该阈值。
精准线、守线、回踩幅度、回踩缩量与趋势判定不变；趋势未确认的回踩仍只标为观察，不冒充买入预警。

- 突破量比开关只影响精准线分支。关闭时，突破日量比仅记录，不作门槛或放量加分；
  缺少有效均量基准时显示为空，不以0冒充实际量比，也不因此否认价格上穿。
- 回踩缩量条件仍保留：信号日成交量不超过突破日的75%；突破日零成交量不能确认缩量回踩。
- 页面可重新启用“精准线启用突破量比过滤”，此时仍使用 `breakout_vol_mult`，默认1.5倍。
  旗形突破的量比要求始终保持原规则，不随这个开关关闭。

- 页面“回调天数”默认 **1～10个交易日**，可设置 **1～60**，对应 `min_pullback_days` / `max_pullback_days`。
- 突破当天为0，下一根交易日K线为1；计算的是**突破日到信号日回踩确认的间隔**，不是连续阴线数量。
- 上下限都包含：3～7表示第3至第7个交易日，5～5只取第5天。周末不计入交易日。
- 突破搜索同步扩展到所选上限，设20天就能识别20天前的突破，不再被原先10根搜索窗口截断。
  仍选最近一次符合当前规则的突破，不能为满足下限、守线或突破前路径过滤而改选更早突破。
  关闭量比过滤后，新一次收盘上穿也会重新计时，突破当天不会被当作回踩。
- 之前确定的“最高价不超过精准线1.50倍”和“没有连续30天有效收在线上”同时保留，
  两项检查仍只看最近已确认阻力点到本次突破之前，不看突破后行情。
- 联合模式中这些条件仅约束精准线分支；旗形保持独立。只看这一形态时选择“精准线回调”。
- 关闭“只选突破后回踩”可继续查看尚待确认的观察机会，回调天数仍用于买入预警的确认。
- 新批次保存全部条件，详情和回测继承同批次参数；`pullback_check` 记录设定范围、实际距突破天数与确认状态。
  旧批次缺少这些字段时仍用旧逻辑；`max_pullback_days=null` 专用于兼容旧窗口，下限须为1。
  旧 `min_days_since_breakout` / `max_days_since_breakout` 参数保留兼容，新页面不再使用。
- 旧批次缺少 `require_breakout_volume` 时按开启处理，旧结果不会被追溯改成价格突破。
  新筛选、详情与回测按批次保存和继承开关，缓存区分开启与关闭；结果保留实际量比与是否要求量比的记录。

## 精准线突破前路径限制

新筛选同时要求以下两项，不满足任一项就排除该精准线形态：

1. 期间最高价不超过线价的 **1.50倍**，即 `max_prebreakout_extension_pct=0.50`。
2. 期间没有连续 **30个交易日**有效收在线上，即 `prebreakout_reject_above_days=30`。
   有效收线上定义为 **收盘价严格大于线价的1.02倍**，缓冲参数为 `prebreakout_above_buffer_pct=0.02`。

这是独立的历史路径过滤，不改变精准线价格、原有回踩距离上限或突破日量比门槛。
其中1.50倍是**日线最高价**上限；有效收线上按**收盘价**判断。
另一个 `breakout_vol_mult=1.5` 是成交量过滤的门槛，不是要求收盘价达到线价1.5倍。
精准线分支仅在 `require_breakout_volume=true` 时要求突破日成交量达到此前10日均量的1.5倍，
新筛选默认不启用。连续站上30天、最高价1.50倍和回调窗口是互相独立的条件。

- 起点为本次突破之前已经确认的最后一个阻力波峰，支撑回踩点不重置起点。
- 两项均检查该触点之后、突破日之前的日线，不包含触点当天、突破当天或之后的行情；不截成最近10天。
- 最高价恰好等于线价1.50倍允许，上影线超限也会被排除。
- 连续29天允许，达到30天即排除；中间任何一天收盘不高于1.02倍，连续计数归零。
  按交易日K线计数，不按自然日；不累计不连续的站上天数，最高价、开盘价不能替代收盘价。
- 不能通过改用更早一次突破绕过检查。没有突破时标为待验证，不误记为通过。
- 联合模式只过滤精准线分支，旗形仍可独立入选。检查结果保存在 `prebreakout_check`，
  包括起点、确认日、区间最高价与日期、最长连续天数及起止日期、每项是否通过。
- 幅度界面输入50，API传0.50；缓冲界面输入2，API传0.02。幅度或缓冲的0表示零容忍，不表示关闭。
  API的幅度或连续天数传 `null` 可独立关闭对应条件；连续天数须为1～250的整数，0不合法。
- 旧批次各自缺少的限制保持未启用，已保存的20%上限不改成50%、10天连续站上阈值不改成30天；
  详情和回测继承批次原值，缓存按全部参数区分。
  新规则需重新筛选后生效，不重写旧结果。这是指定形态规则，尚未验证它能提高胜率。

## 旗形突破（实验模式）

工作台默认使用 `联合筛选`：精准线回调或旗形任一种命中即可入选，也可单独选择 `精准线回调` 或 `旗形突破`。
旗形可选择 `全部方向`、`下倾旗形`、`水平旗形`、`上倾旗形`；方向不表示预期胜率的高低。

- 同股只返回一行，`pattern_matches` 保留实际命中的形态与各自的确认状态。未满足条件的分支不加标签。
- 已确认任一种形态即进入预警列表；另一种若仅形成中，标签明确标注“待确认”。两种都在观察阶段则进入观察机会。
- 联合模式只取主要形态的得分，不叠加分数。详情可点击形态标签查看各自条件与图形。
- 同股同日回测只计一笔；未确认的旗形标签不计入旗形突破胜率。历史记录保留当时命中的标签。
- 新扫描/API默认联合模式；旧批次没有 `strategy_mode` 时仍按原精准线策略回放，不追溯补标签。
- 独立识别旗杆与整理通道，允许旗面上行并超过旗杆终点价格。

## 使用建议

默认扫描全部 A 股（约 5000 只，4 线程并发）。实际耗时受行情接口限流和网络质量影响。
扫描在服务端后台运行，
点完「开始筛选」就可以切走做别的事，回来页面会自动接上进度。想快速试跑就把
「扫描数量」改成 50-200；选 `sample` 数据源则只用 3 只内置示例股票，秒出结果，
适合验证页面和交互。

数据源不稳时「失败」计数会上升，程序已对每只股票自动重试 3 次。若失败率很高，
通常是本机网络/代理的问题而不是程序问题——可以先用单股分析输入一个已知代码（如
`600519`）验证：若返回「未获取到行情数据，可能是股票代码不存在，或数据源暂时不可用」，
说明是数据源侧的问题。

页面中的分数是形态与量价条件的结构得分，不代表胜率或收益概率。

### 2026-09-05 修订与附加条件评估

- 确认峰谷时保留拐点至确认日之间已经出现的真实极值，不从确认日重新起算。
- 行情更新失败时，缓存只用于查看历史；新的扫描会将其计入失败及 `stale_count`，不产生新预警。
- 行业缓存按有效期和日期重新获取；过期回退不刷新原时间戳，也不计入综合分。
- 回踩量同时与突破量和突破前常态均量比较。新增常态量风险提示，不增加未经验证的硬过滤。
- 新复盘的 `net_return_*` 按下一根有效日线开盘入场、固定周期退出计算，双边费用及滑点合计假设20bps。
  一字或零成交量日拒绝入场；卖出受阻则延后；不假设买入当天就能卖出。
  这是日线成交近似，不包含真实排队成交、完整停牌日历及历史风险警示状态。
- 原 `forward_return_*`、历史批次和旧报告保留；页面明确区分净收益与旧版信号涨跌统计。
- `signal_offset=1` 仍表示数据中的倒数第二根，并非自动选择最新完整交易日。
  收盘后使用这一设置会多回看一日；历史信号回放不代表实际扫描当时已能收到该预警。
- 部署服务器时使用 `TZ=Asia/Shanghai`，保持行情缓存与行业快照时间口径一致。

### min_line_strength 的调参结论（2026-09 实测，勿重复踩坑）

以下是旧版本、未扣费的历史调参记录，不代表本次修正后策略的交易胜率。

`min_line_strength` = 落在同一条 ±`error_margin_pct` 价格带里的波峰个数下限，
即「这条精准线至少要被撞几次才算数」。**默认 3，实测结论是保持不变。**

300 只 × 回看 500 日 × 9 档门槛（2/3/4/5/6/7/8/12/20）的时点化回放：

| 门槛 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 12 | 20 |
|---|---|---|---|---|---|---|---|---|---|
| 胜率 | 51.6 | 51.7 | 52.4 | 53.9 | 54.2 | **54.4** | 53.5 | 51.6 | 51.1 |
| T+20 中位 | 0.42 | 0.49 | 0.55 | **0.81** | 0.77 | 0.79 | 0.61 | 0.53 | 0.21 |

曲线是倒 U 形，在 7 附近见顶后回落到基线。但顶点相对默认值 3 的改善
（胜率 +2.62pp、均值 +0.69pp）经按股票聚类的 bootstrap（5000 次）检验，
95% CI 分别是 [-0.25, +5.51] 和 [-0.19, +1.62]，**两者都跨 0**，
而代价是信号数减少 57%。不划算。

门槛 20 的均值最高（3.42%）具有欺骗性：它的中位数最低（0.21%）、胜率回到基线、
样本仅剩 141 —— 少数大赢家拉高均值，不是稳定优势。看中位数和胜率，别看均值。

三条方法论教训：

1. **量强度分布必须用完整历史**。生产扫描喂的是全部 K 线，用近 500 根量会把强度
   压低一倍以上（中位 4 vs 9、最大 9 vs 25），据此选的扫描区间会整个错开。
2. **不能用「从低门槛结果里切片」代替实跑**。提高门槛会改变部分股票选中的是
   哪条线，不只是过滤信号。这个二阶效应在低门槛处 <0.5pp，到门槛 8 就反了号
   （切片预测 2.87%/55.7%，实跑 2.59%/53.5%）。
3. **不同门槛的结果是嵌套样本，两两 t 检验前提不成立**。要么在单一样本内做回归，
   要么在同一次重采样里同时计算两档再比差值。信号之间还按股票聚集，朴素 p 值偏小。

## 接口速查

| 接口 | 说明 |
|---|---|
| `POST /api/scans/run` | 提交扫描任务，立即返回 `{scan_id, status, ...}`；已有任务在跑时返回该任务的 id |
| `GET /api/scans/{id}/progress` | 查询进度与已命中结果 |
| `GET /api/scans/active` | 当前运行中的任务，空闲时返回 `null` |
| `GET /api/scans/latest` | 最近一次完成的扫描（含完整结果） |
| `POST /api/watchlist/refresh` | 后台刷新观察池行情并计算相对加入价的涨跌 |
| `GET /api/stocks/{code}/analysis` | 单股诊断，恒返回 200 + `{found, stage, message, result, chart}` |
| `GET /api/stocks/{code}/detail` | 单股完整行情、技术分析和市场指标 |
| `GET /api/stocks/{code}/company` | 公司资料、股东户数和前十大股东 |
| `GET /api/stocks/{code}/news` | 最新个股新闻 |
| `GET /api/stocks/{code}/industry-market` | 所属行业指数完整 K 线 |
| `GET /api/stocks/{code}/backtest` | 单股历史预警时点化复盘 |
| `POST /api/backtests/run` | 后台提交批次历史复盘 |

扫描失败不会返回 HTTP 500，而是通过 `/progress` 的 `status: "failed"` 与 `error` 字段暴露。
